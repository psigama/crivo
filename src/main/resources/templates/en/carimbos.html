Timestamps of the trail

The audit trail is chained by hash: altering one event breaks the chain. But whoever operates the installation could, in theory, rewrite the whole chain. To close that door, the head of the trail is timestamped by an independent authority, which attests that that hash already existed at that instant. Since each event contains the hash of the previous one, one timestamp holds for the whole trail up to that point — including the preregistration and the commitment to the seed of each study.

Only the hash leaves the server: 32 bytes that reveal no content and no personal data.

Timestamps granted

Authority: FreeTSA (https://freetsa.org/tsr). Timestamped right after each freezing, amendment, seed revelation and report, and once a day if the trail has changed.

How to check without trusting Crivo

Download the authority's certificate and the root certificate straight from its own site, not from here, and check the SHA-256 of each file against what it publishes. These are the values this installation uses:

tsa.crt
hash
cacert.pem
hash
curl -O https://freetsa.org/files/tsa.crt
curl -O https://freetsa.org/files/cacert.pem
sha256sum tsa.crt cacert.pem

openssl ts -verify -digest HASH_CARIMBADO -in ANC-XXXXXXXX.tsr \
    -CAfile cacert.pem -untrusted tsa.crt

On Windows, Get-FileHash in PowerShell gives the SHA-256, and openssl comes with Git for Windows. The expected result is Verification: OK.

The token proves that the hash existed at the attested time. To know that this hash is the one of the published trail — and not just any number — recompute the chain: airlab verify does both checks, and the verification package of each completed study carries the trail up to the report, for anyone who wants to redo them from the outside with airlab verificar-pacote.

What this timestamp does not prove. It does not prevent a rewrite made before the first timestamp after a milestone — in normal operation, about a minute. And it is worth as much as the authority that signs it: there is only one, for now.
