The audit trail

How to check the integrity of the chain

Anyone can check the integrity of the chain without asking anyone for permission and without trusting a page: the verification runs outside the application, from the same artifact.

Command-line verification:

./scripts/airlab.sh verify .\scripts\airlab.ps1 verify

The command checks the hash chain, the hash of each version of the preregistration and, in studies already unblinded, replays the draw from the seed. It exits with a non-zero code if anything does not check out.

The timestamps, the preregistration and the revealed seed can be checked by anyone. At the end of each study, the verification package carries the rest: the trail up to the report, each submission with the list of eligible mediums, the responses and the readings, with no names at all. With it, airlab verificar-pacote replays, with no database and no server, the chain of the trail, the draw of the medium for each pair, the commitment of each reading, the scoring and the analysis — and arrives at the same number, or shows that it does not. Only the commitments of the requests remain attested by the platform: they cover the first name of the deceased person, which is not published.

Open source

Download it, fork it, propose changes

The whole project lives in a public repository — code, specification, technical plan, bibliography and the database migrations. There is no internal version different from this one.

github.com/rogeriocisi/crivo

Clone and run

Single prerequisite: a JDK 21 or newer.

git clone https://github.com/rogeriocisi/crivo.git cd crivo && ./scripts/start.sh

On Windows, scripts\start.cmd — it is the path that works on a freshly installed machine, because PowerShell refuses unsigned scripts by default. The script builds the project, starts the embedded PostgreSQL and runs the application at 127.0.0.1:8080.

Fork and propose

Contributions come in through a pull request.

git switch -c minha-contribuicao ./mvnw test

Make the fork on GitHub, work on a branch, run the suite and open the pull request. Small commits, messages in the Conventional Commits style, and no feature without the corresponding specification — the rule is in the repository's CLAUDE.md.

Disagree

A methodological objection is a contribution.

Found a hole in the blinding, a bias in the analysis or a reference that contradicts a design decision? Open an issue. The map of published criticism → control in the system is in docs/REFERENCES.md, including the lines where nothing in the software answers.
